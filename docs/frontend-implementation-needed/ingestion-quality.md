**Place in:** recruiter-only `/dashboard/candidates/import`, extending [batch-processing.md](batch-processing.md) and [ingestion.md](ingestion.md). Match Pareto's established ivory/navy/cobalt navigation and compact tables.

## Goal

Make processing quality and human verification real rather than implied. Recruiter can inspect each job's measured stages, view original private resume, compare the AI-extracted candidate against actual evidence, correct/approve/reject fields, and see an immutable who/when/what-changed audit trail. A recruiter can inspect aggregate import throughput/retry/review metrics without seeing fake quality confidence scores.

## Suggested UI sections

**Import history:** existing rows gain `reviewState` ("Unreviewed", "Needs review", "Human verified"), job stage, last attempt time and action "Review". Avoid a confidence percentage unless calibrated metrics actually exist.

**Candidate review side panel:** show original short-lived private document link, the current candidate profile, fields marked undocumented (null), source evidence quotes and PDF page numbers where supplied, and an editable form matching the backend full schema. The UI must explicitly distinguish (1) model-provided field with source quote, (2) manually corrected/approved field with audit actor/date, and (3) unknown field. Never retain a model quote beside a changed value; the backend removes stale model evidence.

**Review actions:** `Approve` existing extraction, `Save corrections` (mandatory reason), or `Reject extracted profile` (mandatory reason, irreversible loss of the current searchable candidate unless corrected again). Require visible checkbox “I checked the original source document” and set `confirmedAgainstSource:true`. Do not send the declaration automatically or pre-check the box. Include `expectedVersion` from the latest GET; on HTTP 409 reload and let user compare the latest revision rather than overwriting silently. Correction supplies a **complete typed profile**, not an arbitrary field patch. On approved/corrected terminal profile show "Human verified" only because the user explicitly attested. It is not an independent third-party credential check.

**Extraction audit:** chronological events for model extraction, no-profile-review state, human correction/approval/rejection, changed-field names, timestamps and read-only before/after values. This is private candidate data. Filter history by the selected owned document, never display across accounts.

**Job details/processing analytics:** use measured `durationMs`, `parseMs`, `modelMs`, `persistMs`, `sourceChars`, `evidenceCount`, `verifiedFields`, `provider` and `extractorVersion` returned by the history endpoint. Hide or mark “Not recorded” for null values. `modelMs` is not token cost or provider invoice. Aggregated metrics section: group counts by queue/document/review state, completed attempts, retry/recovery counts, average and p95 measured durations, corrected fields and approvals. The API returns caveats—show these near “quality” metrics.

**Synthetic quality evaluation:** development/operator-only report generated by `pnpm --filter @pareto/backend ingest:evaluate`. It is a labelled offline-fixture benchmark, not live hiring accuracy. Do NOT show its precision/recall as production model quality on the recruiter dashboard.

## API contract

All APIs are same-origin, authenticated, scoped to the signed-in recruiter and `Cache-Control: private, no-store`. No model keys/worker tokens in frontend.

| Method | Route | UI |
| --- | --- | --- |
| GET | `/api/v1/imports/:id/profile` | Return `{documentId, documentStatus,reviewState,reviewVersion,reviewedAt,candidateId,profile}`. Profile has displayName, roleTitle, city, experienceMonths, noticePeriodDays, industry, education, employmentType, skills (nullable array), pastRoles, certifications. |
| POST | `/api/v1/imports/:id/profile` | JSON action `approve`, `correct` or `reject`. Must include current `expectedVersion` and literal `confirmedAgainstSource:true`. Correct requires full typed profile + reason 8–250 chars. Reject requires reason. |
| GET | `/api/v1/imports/:id/audit` | `{documentId,events:[...]}` each event `action, reviewVersion,changedFields,before,after,reason,provider,extractorVersion,attempt,createdAt`. Limit 100 newest. |
| GET | `/api/v1/imports/metrics?days=30` | 1/7/30/90-day owner-only status distributions, attempt timings and correction/review counts; no raw resumes. |
| GET | `/api/v1/imports/:id/job` | Existing job+attempt history expanded with measured fields and version identifier. |
| GET | `/api/v1/imports` | Existing list includes reviewState, reviewVersion, reviewedAt. |

### Review actions

```json
{"action":"approve","expectedVersion":0,"confirmedAgainstSource":true}
```

```json
{
  "action":"correct","expectedVersion":0,
  "confirmedAgainstSource":true,
  "reason":"Verified work history against the original resume.",
  "profile":{
    "displayName":"Asha Nair","roleTitle":"Backend Developer",
    "city":"Hyderabad","experienceMonths":72,"noticePeriodDays":null,
    "industry":null,"education":null,"employmentType":null,
    "skills":["Java","AWS"],"pastRoles":[],"certifications":[]
  }
}
```

```json
{"action":"reject","expectedVersion":0,"confirmedAgainstSource":true,
 "reason":"This profile combines two different people's records."}
```

Do not automatically infer a missing notice period is zero. For `skills`, `null` means unknown; `[]` means the reviewer explicitly confirmed an empty list. Numeric experience is integer months (0–720); notice is days (0–365). Backend rejects invalid unknown fields and control characters.

## Error and interaction handling

- 401: require sign-in; remove cached private details and signed URLs.
- 404: import unavailable or belongs to a different recruiter; generic message without revealing its existence.
- 409: active job, stale review version or profile missing; **never** silently retry against an old revision. Reload the current state and explicitly request reconfirmation.
- 413/415/422: body/type/validation error, show safe action-specific hint.
- 500/503: temporary server or Storage issue; preserve unsubmitted editor text only in component state, not persistent localStorage.
- Only existing terminal jobs can be reviewed. Job status remains authoritative: queued/running actions are disabled, no fake "approved" badges.
- Confirm rejection: the candidate becomes unavailable to search until corrected; the original private document and audit are retained.
- No PII in frontend logs, metrics telemetry, browser analytics, URL query strings or clipboard without user action.
- Responsive/keyboard/screen-reader accessible input fields, focus, error summary, live announcements for saved state, and reduced-motion support.
- A browser must never treat AI output as a permission grant, original resume as instructions, or the review checkbox as proof of objective credentials.

## Acceptance checklist

- [ ] Owner-scoped review detail loads; foreign/unsigned sessions cannot see private profile or audit.
- [ ] Correct and approve operate against current expected version and require deliberate source attestation.
- [ ] Two concurrent reviewers produce an actionable 409 conflict rather than last-write-wins.
- [ ] Changed model evidence is not misleadingly shown beside manually corrected fields.
- [ ] Reject removes candidate from search; audit remains visible; subsequent source-checked correction can restore.
- [ ] Input validation: bounded text, nullable fields, days/months, canonical skills and complete profile payload.
- [ ] Measured job timings show null as “Not recorded”; no invented confidence/cost/progress.
- [ ] Aggregate operational metrics scoped to recruiter; warnings distinguish review activity from model accuracy.
- [ ] No new UI for model cost/quota or calibrated accuracy without actual backend support.
- [ ] Existing import, search, diagnostics, simulator and near-match regressions pass.

## Delivered frontend (PR #20)

The importer detail surface provides the complete typed profile editor, nullable unknowns (including unknown-vs-empty skills), required explicit source attestation, optimistic `reviewVersion` compare-and-swap, correction and rejection reasons, approval/rejection confirmation, conflict reload, and chronological audit before/after values. Changed-source quotes are deleted by the backend, not fabricated by the browser. `metrics.tsx` displays actual owner-scoped attempt durations and review activity with returned accuracy caveats. Signed-in approval/correction/rejection and live provider quality require an authorized dedicated recruiter/bucket/worker environment; CI only verifies the code and signed-out API security boundary.
